## 2024-04-04 - Parameter Fitter Inner Loop Allocation Bottlenecks
**Learning:** `interpolateRow` in `paramFitter.ts` was identifying target times using `findIndex` (O(N) linear scan) and allocating new arrays on *every evaluation* of *every data point* via `rows.map(r => r.time)` and `Object.keys(row)`. Given mathematical optimization routines (like Nelder-Mead and DE used here) can run thousands of iterations each producing thousands of rows, these allocations cascade into massive memory pressure and GC pauses.
**Action:** Always prefer O(log N) binary searches over O(N) array scans when dealing with pre-sorted time-series data. Replace `Object.keys(obj).forEach` or `Object.entries(obj)` with `for...in` loops in highly iterative hot paths to completely bypass object allocation overhead in V8.
