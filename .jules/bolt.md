## 2024-06-15 - Optimizing isFunctionalRateExpr by removing ANTLR AST parser
**Learning:** Found a massive performance bottleneck specific to the engine's hot paths evaluating mathematical expressions for rules (`isFunctionalRateExpr`). Heavy AST parsers like ANTLR (`getExpressionDependencies`) are extremely slow for tight loops evaluating simple mathematical string dependencies, taking thousands of milliseconds for 10k evaluations.
**Action:** When optimizing hot paths evaluating mathematical expressions or searching for string patterns, avoid using heavy AST parsers. Instead, implement fast, zero-allocation character scanning loops using `charCodeAt` to manually tokenize and identify dependencies. This reduces overhead by orders of magnitude (from ~2898ms down to ~22ms for 10k evaluations).
