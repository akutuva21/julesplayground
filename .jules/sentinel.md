## 2024-06-15 - Secure `new Function` with strict validation in JITCompiler.ts
**Vulnerability:** The methods `compileSSAPropensities` and `compileSSAPropensitiesWithFunctionalRates` in `JITCompiler.ts` dynamically assembled JavaScript code strings and passed them to `new Function(...)` to evaluate reaction propensities. This allowed for potential code injection.
**Learning:** This existed to provide a "fast path" for propensity calculation in mass-action models. Removing `new Function` would degrade performance. Instead, to maintain the performance speedup while satisfying CodeQL checks and security invariants, we must explicitly prove that all inputs to the source template string are mathematically safe primitive numbers.
**Prevention:** Rather than avoiding dynamic code generation completely, apply strict runtime structural validation and casting (like `typeof value !== 'number' || !Number.isFinite(value)`) before injecting ANY variable into a code evaluation template. This mathematically prevents arbitrary code breakout from the interpolation context.
