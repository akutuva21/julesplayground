## 2026-05-16 - 🛡️ Sentinel: [CRITICAL] Fix arbitrary require vulnerability in CVODE VM context
**Vulnerability:** Arbitrary module `require` vulnerability inside a `vm.Script` VM context. The `packages/engine/src/services/simulation/cvode_node.ts` passed an unrestricted `require` instance into `vm.createContext()`, allowing the executed loader script to require and execute any Node.js module (e.g. child_process), posing a severe RCE risk.
**Learning:** `vm.Script` does not securely sandbox the environment by itself. If you pass dangerous globals like `require` into the context, the script has full access to them. The Emscripten loader `cvode_loader.js` only needed access to `path`, `fs`, and `crypto`.
**Prevention:** When creating `node:vm` contexts, always construct a restricted execution environment. Use a `safeRequire` wrapper with a strict string-matching allowlist (`new Set(['path', 'fs', 'crypto'])`) to block access to unauthorized modules while allowing necessary ones to function correctly.
